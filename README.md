# DSH 桥接 · Tavern Bridge

让 **DSH**（电脑上的 AI）读到你**酒馆**里的东西：MVU 变量、实时消息、其它扩展设置。

这是一个**酒馆扩展** + 一个**中继**。两个都要装，缺一不可。

## 为什么需要中继

```
┌─────────────┐   POST/长轮询   ┌──────────────┐    HTTP    ┌─────────┐
│  酒馆扩展    │ ─────────────▶ │  中继(电脑)   │ ◀───────── │   DSH   │
│ (手机/电脑)  │ ◀───────────── │  :17651      │ ─────────▶ │         │
└─────────────┘                 └──────────────┘            └─────────┘
```

酒馆扩展跑在浏览器里，**浏览器不能监听端口**，所以 DSH 没法直接连它。
中继是个很小的 Node 进程（零依赖），只做转发和排队，不碰酒馆数据。

## 它能拿到什么（REST 拿不到的）

| 能力 | 说明 |
| --- | --- |
| **MVU 变量** | `Mvu.getMvuData()` 的 `stat_data`——客户档案、训练次数、进度 |
| **实时快照** | 当前角色、聊天 id、楼层数、绑定的世界书 |
| **扩展设置** | 其它扩展的 `extensionSettings`（只读） |
| **后台生成** | 用酒馆当前模型写一段（不写正文） |
| **往正文发消息** | 需要打开 `allowWrite`（默认关） |

普通 REST 就能拿的（角色卡、世界书、聊天记录）走中继的直连通道，不经过扩展。

## 安装

### 1. 中继（电脑上）

```powershell
node relay/relay.js --port 17651
```

可选参数：

```powershell
node relay/relay.js --port 17651 --token 你的token --tavern http://192.168.1.20:8000
```

启动后会打印：

```
  DSH 桥接中继已启动
  ─────────────────────────────────────────
  端口      17651
  Token     a1b2c3d4e5f6...

  填到酒馆扩展里（酒馆在手机上用局域网地址）：
    以太网        http://192.168.1.13:17651
    本机          http://127.0.0.1:17651
```

**token 不传就自动生成**。酒馆在手机上时，用局域网那个地址。

### 2. 酒馆扩展

把本目录整个放进酒馆的第三方扩展目录：

```powershell
# 电脑上的酒馆
Copy-Item "D:\牢凌的知识库\ST角色卡库\50-插件\st-dsh-bridge" `
          "<SillyTavern>/public/scripts/extensions/third-party/" -Recurse

# 手机上的 TT：用酒馆的「安装扩展」功能，填这个仓库地址
```

**然后重启酒馆**（扩展列表是启动时扫描的）。

### 3. 在酒馆里配置

扩展设置里找到「DSH 桥接」：

| 字段 | 填什么 |
| --- | --- |
| 启用桥接 | 打开 |
| 中继地址 | 中继启动时打印的那个（手机上的酒馆填局域网地址） |
| Token | 中继启动时打印的那串 |
| 允许 DSH 往正文发消息 | 需要时才开（默认关） |

状态栏会显示「已连接 / 连不上」和具体原因。

## DSH 侧怎么用

```powershell
# 查状态（能看到 MVU 变量）
curl "http://127.0.0.1:17651/dsh/status?token=你的token"

# 发指令
curl -X POST http://127.0.0.1:17651/dsh/call `
  -H "Content-Type: application/json" `
  -d '{"token":"你的token","kind":"mvu"}'
```

支持的 `kind`：

| kind | 作用 | 参数 |
| --- | --- | --- |
| `snapshot` | 当前完整快照 | — |
| `messages` | 最近消息 | `limit` |
| `mvu` | MVU 变量 | — |
| `send_message` | 往正文发用户消息 | `text`（需 allowWrite） |
| `generate` | 后台生成 | `prompt` / `system` / `length` |
| `extension_settings` | 读某扩展设置 | `key` |
| `ping` | 连通性 | — |

## 排查

**扩展显示「连不上中继」**
- 中继在跑吗？（`node relay/relay.js`）
- 地址对吗？手机上的酒馆要填**电脑的局域网 IP**，不是 `127.0.0.1`
- token 一致吗？（大小写敏感）
- Windows 防火墙放行了吗？

**扩展根本没加载**
- 重启酒馆（扩展列表启动时才扫描）
- 检查 `manifest.json` 在不在、`index.js` 能不能访问
- 酒馆设置 → 扩展里看有没有「DSH 桥接」

**能连上但 MVU 是空的**
- 没装 MVU 框架（MagVarUpdate / 酒馆助手），或这个聊天还没初始化变量
- 先聊几句让 MVU 跑起来

## 技术细节

### 为什么用长轮询而不是 WebSocket

浏览器到局域网 `http://` 的 WebSocket 会被混合内容策略挡掉（`ws://` 不算安全）。
长轮询没有这个问题，延迟也够用（有指令时立刻返回）。

### 酒馆扩展的加载顺序

酒馆按 `loading_order` **串行**加载扩展。这个扩展是 90，排在很多扩展后面，
所以打开酒馆后要等几秒它才出现——**这不是没加载**。

### token 校验

中继的所有端点都要 token，用常量时间比较（`timingSafeEqual`），防止局域网里别人乱用。
